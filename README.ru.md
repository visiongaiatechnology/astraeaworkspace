## Что такое Astraea Workspace?

Astraea Workspace — это офисный и продуктивный рабочий комплекс для ПК, созданный на основе ясного принципа:

**Ваша работа должна оставаться доступной, понятной и находиться под вашим полным контролем даже тогда, когда недоступны никакие облачные сервисы.**

Комплекс объединяет работу с документами, управление знаниями, творческие инструменты, автоматизацию, локальный поиск, защищенное хранение и кросс-приложенческие рабочие объекты в единой среде настольного компьютера.

Основные рабочие процессы ориентированы на **локальную обработку (Local-first)**. Сетевые возможности представляют собой явно подключаемые функции, а не обязательное условие для открытия или редактирования ваших файлов.

Astraea — это не просто набор изолированных редакторов с обновленным интерфейсом. Все приложения платформы разделяют единую модель рабочих объектов — **Workspace Object Model (WOM)**, благодаря чему совместимые объекты можно связывать, внедрять, индексировать в поиске, автоматизировать и повторно использовать по всей системе.

### Принципы продукта

- **Локальная работа по умолчанию** — документы и состояние рабочей среды остаются на вашем устройстве, если пользователь явно не включил сетевой компонент.
- **Нулевая продуктовая телеметрия на уровне архитектуры** — для штатной работы системы не требуется никаких механизмов сбора поведенческой аналитики.
- **Автономность и режим Air-Gap** — ключевые сценарии функционируют без учетных записей в облаке и постоянного подключения к Интернету.
- **Open Core, навсегда бесплатный** — базовая редакция Astraea Open Core распространяется по лицензии GNU AGPLv3 и остается бессрочно бесплатным фундаментом продукта.
- **Четкая граница Premium** — редакция Premium расширяет систему инструментами управления проектами, структурированными базами данных, командными пространствами и зашифрованной совместной работой. Она не преследует цель сделать бесплатную версию искусственно неполноценной.
- **Сквозные объекты между приложениями** — Writer, Grid, Whiteboard, Publish, Insight, Automate и другие приложения обмениваются совместимыми рабочими объектами напрямую, без необходимости сводить всё к обычному копированию текста.
- **Безопасность, подкрепленная реальными механизмами** — криптографические алгоритмы, хранение ключей, сетевые политики и доказательства сборки документируются прямо и открыто, без абстрактных рекламных формулировок.

# Редакции

## Astraea Open Core — Бесплатно навсегда

Astraea Open Core — это основа платформы для индивидуальной продуктивной работы.

Это **свободное программное обеспечение с открытым исходным кодом под лицензией GNU AGPLv3**.

Приложения, включенные в Open Core, остаются неотъемлемой частью бесплатной редакции. Дальнейшее развитие Premium может приносить новые возможности для корпоративного управления, но назначение Open Core — оставаться полноценным рабочим продуктом, а не ограниченной по времени демонстрационной версией.

## Astraea Premium — Организация, данные и сотрудничество

Astraea Premium — коммерческое расширенное надмножество.

Оно включает в себя всё наполнение Open Core и добавляет шесть специализированных приложений для управления проектами, структурированных бизнес-данных, командных рабочих пространств и зашифрованной синхронизации между устройствами.

> **Open Core — суверенный персональный офис. Premium объединяет организационную среду вокруг него.**

# Workspace Explorer

Astraea Workspace оснащен централизованным **Workspace Explorer**, позволяющим быстро находить и использовать ранее созданные документы без необходимости помнить, в каком редакторе они открывались.

Explorer обеспечивает сквозной доступ ко всем наработкам:

```text
Все файлы
Недавние
Открытые
Избранное
Коллекции
Поиск
Предпросмотр
Открыть исходник
Вставить из Workspace
Перетаскивание (Drag & Drop)
```

Ключевое отличие заключается в семантической обработке.

Файл `.vgrid`, перенесенный в Writer с помощью Drag & Drop, не воспринимается как неопознанный бинарный массив. Astraea предлагает действия, осмысленные для источника и приемника:

```text
Живой диапазон (Live range)
Фиксированный снимок (Frozen snapshot)
Вставить как таблицу Writer
Открыть исходник
```

Эта же схема обеспечивает прозрачное взаимодействие между Writer, Grid, Present, Whiteboard, Publish, Insight, Automate и другими модулями системы.

# Локальная работа не означает изоляцию

Astraea ориентирована на работу на локальном устройстве, однако принцип Local-First не означает запрет на любое взаимодействие.

Редакция Open Core функционирует полноценно и автономно без регистрации в облаке.

Premium дает возможность подключить сквозное зашифрованное хранилище, командные пространства и сервисы GaiaCom, когда это требуется пользователю или организации.

Любые сетевые протоколы остаются строго регламентированными политиками безопасности и не влияют на право собственности на локальные файлы.

# Архитектура безопасности

Astraea Workspace построена на базе концепции **нулевого доверия для локальных вычислений (Zero-Trust Local-Computing)**.

В проекте подробно раскрываются конкретные технические решения вместо расплывчатых маркетинговых фраз вроде «безопасность военного уровня».

## Зашифрованные контейнеры VWC

Файлы документов сохраняются с использованием контейнерного формата Astraea.

Комплекс мер безопасности включает:

- Аутентифицированное шифрование на базе современных режимов AEAD, таких как **AES-256-GCM** и **ChaCha20-Poly1305**;
- Алгоритм **Argon2id** для формирования ключей на основе парольной фразы;
- Системный контроль подлинности и целостности содержимого контейнеров;
- Строго ограниченные и валидируемые процедуры разбора файлов на границах доверия;
- Четкое версионирование и документированные механизмы обновления форматов.

Конкретные криптографические профили и алгоритмы относятся к проектной документации и отчетам верификации, а не к рекламным материалам.

## Криптографическое ядро VGT Infinity

Astraea Workspace использует собственную разработку — **VGT Infinity Cryptographic Core** в качестве первичного модуля безопасности.

В репозитории компонент размещен в директории:

```text
vendor/infinity
```

и предоставляет расширенный набор алгоритмических средств:

- Гибридные классические и постквантовые протоколы выработки общих ключей;
- Поддержка стандартизированного семейства **ML-KEM**;
- Алгоритмы цифровой подписи семейства **ML-DSA** и сопутствующие примитивы;
- Схемы аутентифицированного симметричного шифрования;
- Многоуровневые композитные профили, объединяющие несколько независимых алгоритмов;
- Разграничение ключевых пространств, проверка целостности и защищенная работа с оперативной памятью;
- Изоляция криптографических провайдеров при их исполнении в отдельных процессах-сайдкарах.

Интеграция Infinity включает специализированные постквантовые и составные конфигурации, выходящие за рамки базового набора ML-KEM / ML-DSA. Конкретный перечень активных алгоритмов и параметры профилей рассматриваются как **доказуемые факты релиза**: итоговый SBOM, lock-файлы, архитектурные спецификации и подписанный манифест служат единственным источником достоверных сведений о сборке.

Это различие принципиально: Astraea не заявляет, что последовательное наложение алгоритмов создает «абсолютную» защиту. Infinity служит надежным внутренним криптографическим уровнем, профили которого проходят регулярные формальные тесты.

## Постквантовая защита

Благодаря интеграции ядра Infinity и нативной архитектуры Astraea поддерживает криптографические методы, готовые к постквантовой эпохе, включая стандарты **ML-KEM** и **ML-DSA** в поддерживаемых профилях.

Постквантовая криптография снижает долгосрочные угрозы расшифровки данных в будущем, однако **не** является универсальной панацеей от всех мыслимых атак.

## NetGate

Сетевой обмен контролируется явными политиками безопасности, а не разрешается по умолчанию.

Там, где задействован механизм NetGate, исходящие подключения проверяются по белому списку (allowlist) и могут блокироваться еще до отправки на прикладном уровне. Все внешние адаптеры и каналы совместной работы обязаны соответствовать установленным правилам.

## Аппаратная защита ключей средствами ОС

Astraea взаимодействует с системными хранилищами учетных записей при их наличии:

- **Windows:** DPAPI / диспетчер учетных данных Windows
- **macOS:** Служба связки ключей (Keychain) с задействованием Secure Enclave (при поддержке оборудованием)
- **Linux:** Хранилища на базе спецификации Secret Service / libsecret

Применение аппаратных криптографических модулей зависит от возможностей конкретного компьютера.

## Доказательства безопасности (Security Evidence)

Официальные сборки сопровождаются проверяемыми данными верификации:

- Полный перечень используемых библиотек и лицензий;
- Спецификация программных компонентов в формате SPDX SBOM;
- Контрольные хеши файлов дистрибутива (SHA-256);
- Заверенный цифровой подписью манифест выпуска;
- Сведения о цепочке и среде сборки (provenance).

Состав файлов, опубликованный с конкретным релизом, имеет решающую юридическую и техническую силу.

### Преимущества Tauri

Tauri задействует встроенный системный движок WebView операционной системы вместо упаковки отдельного экземпляра Chromium в каждое приложение. Это многократно сокращает объем дистрибутива и потребление ресурсов при сохранении производительности нативного Rust-кода.

Официальная документация по архитектуре Tauri:  
https://tauri.app/concept/architecture/

### Стратегия собственной разработки (First-Party)

Ключевые элементы системы создаются непосредственно разработчиками Astraea без опоры на громоздкие внешние надстройки:

- Workspace Object Model (модель объектов)
- Встроенные редакторы
- Логика документов и структуры связей
- Локальная поисковая подсистема
- Механизм политик (Policy Engine)
- Среда исполнения автоматизаций
- Шлюзы межплатформенного взаимодействия
- Защищенные контейнеры данных
- Интеграция криптографического ядра **VGT Infinity**

# Производительность и потребление памяти

Astraea спроектирована так, чтобы исключить дублирование служебных процессов.

Отказ от встроенного Chromium в пользу системного WebView позволяет снизить фоновые накладные расходы по сравнению с традиционными приложениями на Electron. Тем не менее фактический объем оперативной памяти зависит от операционной системы, количества открытых файлов, реализации WebView, миниатюр, индексов поиска и активных задач.

## Данные предварительных измерений

В ходе внутренних испытаний на эталонной предрелизной конфигурации Windows зафиксированы ориентировочные показатели:

**~100–150 МБ ОЗУ в режиме ожидания (idle) без открытых рабочих документов**

Это **предварительные внутренние замеры**, а не безусловная гарантия для любых условий. Окончательные характеристики будут опубликованы с описанием версии ОС, сборки, выпуска WebView, объема тестовых данных и регламента испытаний.

## Почему мы не используем некорректные сравнения с конкурентами

Сопоставление использования памяти офисными пакетами часто бывает недостоверным.

Пустой документ Microsoft Word, сессия Google Docs в веб-браузере, LibreOffice с запущенным Java-модулем Base и многопоточный настольный редактор создают совершенно разную нагрузку.
